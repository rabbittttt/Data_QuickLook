# 数据速查 · Data QuickLook

> 此公开仓库只保存程序代码；`input_file`、`output_file`、数据库、日志和压缩包不会上传。换电脑后需要自行安全迁移业务 Excel。下载代码可运行 `git clone https://github.com/rabbittttt/Data_QuickLook.git`，以后在仓库目录运行 `git pull` 更新。

通过网页导入 Excel 的数据查询与图表分析工具。主入口为独立网页：数据概览、数据管理、图表展示、收藏的分析。读取和分析不会修改原始 Excel。

已克隆旧仓库的用户可运行 `git remote set-url origin https://github.com/rabbittttt/Data_QuickLook.git` 更新远程地址。旧地址仍可通过 GitHub 重定向访问，建议更新为新地址。

## 安装与启动

所有项目默认共用所在 `Project/.venv`。新电脑先安装 Python 3.11 或更新版本（共享环境要求），在 `Project` 根目录双击“初始化共享环境.cmd”重建共享环境并安装依赖。项目位于 `Project/数据速查/` 时，也可在本项目目录手动安装依赖、启动服务：

```powershell
..\.venv\Scripts\python.exe -m pip install -r requirements.txt
..\.venv\Scripts\python.exe server.py
```

换电脑后应重新创建 `Project/.venv`，不要直接复制旧电脑的虚拟环境。整体移动 `Project` 时保留项目与共享目录的相对位置；`Project` 的上级目录和盘符可以不同。

`启动数据速查.cmd` 从脚本所在目录向上找到最近名为 `Project` 的目录，固定使用其中 `.venv\Scripts\python.exe`，忽略子项目自己的 `.venv`，也不回退 PATH 或 Codex Python。可用 `DATA_QUICKLOOK_PYTHON` 显式指定其他解释器文件；相对路径按本项目目录解析。启动窗口显示所选 Python，并在环境缺失或依赖不全时停止，提示初始化或安装命令。

也可双击 `启动数据速查.cmd`，服务启动后会自动用默认浏览器打开 [本地分析页](http://127.0.0.1:9473)；命令行使用 `..\.venv\Scripts\python.exe server.py --open-browser` 效果相同。重复双击时，如服务已运行，会直接打开现有页面。首次启动的命令窗口需保持打开，服务仅监听本机 `127.0.0.1:9473`。

更新代码后普通刷新网页即可检查新版页面、样式、脚本和图标：静态资源按文件内容自动生成版本号，未变化的内容仍可复用缓存。若更新包含 `server.py` 等 Python 后端代码，需先重启服务（本次缓存策略更新也需要重启一次）。已打开的页面不会自动重载，以保留正在编辑的内容；“同步数据”仍只负责 Excel 数据更新。

## 文件导入与更新

点击“导入文件”批量上传 `.xlsx`、`.xlsm`，单个最大 256 MiB。系统将文件统一保存在持久目录的 `uploads/`，前台无需填写服务器磁盘路径。同名上传需要确认覆盖，文件在确认期间发生变化时需再次确认。损坏或中断的上传不会替换原文件。

上传成功后服务自动处理已登记的上传文件，网页跟踪进度并更新。点击“同步数据”可重试处理已上传文件。共享数据目录为专用自动来源，每 5 分钟检查一次新增和变化的 Excel；发现变化后至少观察 60 秒，文件修改时间和大小保持一致才入库，继续变化则重新计时。解析前后再次核对版本，失败时保留上次成功的数据。其他本地目录不自动接入新文件。网页每 10 分钟检查已入库数据的变化，以接收其他用户在前台上传的更新。

旧版已入库的数据和可访问的原文件继续可查，既有设置文件保留。旧 input_file 目录不再自动接入新文件。旧来源的同名文件与新上传文件分别保留，上传只覆盖系统上传目录中的同名文件。正在编辑的图表发现更新时，保留草稿并允许手动载入更新。

共享目录默认使用原项目同级的 `共享数据/`，递归读取其中所有 `.xlsx`、`.xlsm`。发布部署可用 `SHARED_DATA_ROOT` 指定稳定的共享目录，或通过 `DATA_QUICKLOOK_SOURCE_BASE` 保留原项目基准；无需在网页开放磁盘路径设置。服务启动即执行第一次检查，已入库且未变化的文件跳过，新增和变化文件均需经过稳定观察。

## PlanHub 正式发布

从数据速查项目根目录构建版本包。发布目录已存在时，构建会停止，避免覆盖现有版本。

```powershell
..\.venv\Scripts\python.exe -B scripts/build_release.py --version 2026.11.10.1
```

默认输出为 `output_file/releases/quicklook-2026.11.10.1`，外层只有 `app-release.json` 和 `payload/`。清单记录每个发布文件的大小及 SHA-256。Python 运行时及其依赖安装在版本目录外，按 `payload/requirements.txt` 安装。

沿用原数据时，先停止旧实例并备份原状态目录。下面从数据速查原项目根目录执行，直接指向已有的 `output_file`。发布目录放到其他位置时，将 `$release` 改为实际发布包路径。

```powershell
$release = (Resolve-Path './output_file/releases/quicklook-2026.11.10.1').Path
$python = (Resolve-Path '../.venv/Scripts/python.exe').Path
$env:DATA_QUICKLOOK_DATA_DIR = (Resolve-Path './output_file').Path
$env:DATA_QUICKLOOK_SOURCE_BASE = (Get-Location).Path
$env:DATA_QUICKLOOK_PUBLIC_PREFIX = '/quicklook/'
$env:DATA_QUICKLOOK_PUBLIC_ORIGIN = 'https://planhub.example.com'
& $python -m pip install -r (Join-Path $release 'payload/requirements.txt')
& $python -B -u (Join-Path $release 'payload/server.py') --port 9473
```

- `DATA_QUICKLOOK_DATA_DIR` 保存 `warehouse.db`、`workspace.json` 和 `recognition.json`。新版本直接读取同一目录，跳过旧版启动时的数据源重定位。需要搬动状态文件时，由操作人员离线备份和复制，程序启动时不会搬运旧文件。新上传的 Excel 位于持久目录的 `uploads/`，旧来源文件保持原位置。版本切换时让旧实例退出后再启动新实例。
- 工作区设置里的相对数据源路径按 `DATA_QUICKLOOK_SOURCE_BASE` 解析。复用原 `output_file` 时，默认基准是其父目录。若将状态文件手动放到别处，设置原项目目录为基准，或在工作区设置中使用稳定的绝对路径。生产环境建议为数据目录与基准目录提供绝对路径。独立开发可直接使用现有启动脚本，未配置时沿用项目内 `output_file` 与根路径 `/`。
- 门户固定入口为 `/quicklook/`，整个子树代理到本机服务 `127.0.0.1:9473`。代理保留或剥离前缀均可，须保留查询参数、请求方法、上传正文和内容长度。导入上限为 256 MiB。CSV 和图表图片由浏览器根据已加载的数据生成。
- 将 `DATA_QUICKLOOK_PUBLIC_ORIGIN` 替换为实际门户的协议、域名及非默认端口。HTTPS 终止或后端 Host 被改写时需要该值，来源校验仍按精确匹配执行。健康检查使用后端 `GET /healthz` 或门户 `GET /quicklook/healthz`，返回 `{"ok":true,"app":"quicklook"}`。
- 门户侧只需确认固定入口、通用前缀代理、上传限制和健康探针。后续升级时切换服务指向新版 `payload/server.py`，沿用原持久目录、监听端口和公共前缀，然后重启数据速查。新增前缀内接口不需要另加代理规则。

## 查看原始数据

在“数据管理”选择文件、Sheet 和“此 Sheet 已识别区域”。选择具体区域时仅展示该区域，选择“整个 Sheet”查看原始单元格；支持行列分页和跳转。

工作表目录包含可见、隐藏及深度隐藏 Sheet，不过滤辅助页。文件保存后，网页每 10 分钟检查目录变化并重新读取原表；已导入的区域与图表数据在自动同步完成后更新（后台自动同步仍每 60 秒检查一次）。点击“同步数据”或“保存并同步”时，网页会短暂检查同步完成状态，完成后立即载入更新并停止这次状态检查，不必等待下一个 10 分钟周期。图表正在编辑或弹窗打开时，先保留输入并提示载入更新；离开图表页后，这份草稿不会阻止原表页刷新。新增、改名或删除 Sheet 会重新核对当前目录，失效选择会明确提示。

“字段、筛选与导出”针对当前识别区域操作；识别不正确时使用“修正识别”，或在图表设置中“核对原表 / 修正区域”。手动规则以指定区域的首行为字段名，保存固定范围；新增数据超出范围时需相应扩展。

已删除或改名 Sheet 的旧手动规则会跳过并提示，不会阻止其他 Sheet 更新；规则保留，不修改源文件。当前 Sheet 上超出范围等无效规则仍会报告错误，不会悄悄截断数据。

## 生成与对比图表

1. 进入“图表展示”，按 **文件 → 工作表 → 数据区域** 选择来源。车型不是固定参数；它与区域、门店、版本等一样，只是表中可选的字段或系列。
2. 在统一的“选择指标 / Y 轴”中搜索、多选列名或行名。例如“销量”既可以是一个列字段，也可以是横排月份下面的一行。系统优先展示自动识别的指标方向，选中后按对应方向读取数值，并显示“横轴标签 → 数值”样本。
3. “横轴 / X”随所选指标显示：列指标可选择维度并拆分车型、门店等对比项；行指标可勾选时间或分类列，或批量选择连续区间。行、列指标可以混选，不兼容的横轴自动独立分面。字段与指标均可搜索、全选、清空；全选搜索结果包含全部分页，不限制为 8 条。
4. 在“本次操作”明确选择生成主图、加入已有对比、替换当前图表或更新所选系列。预览与该操作一致，点击对应主按钮后才应用；“取消预览”保留已应用图表。
5. 展开“管理已应用系列”可编辑或移除系列。先应用一组，再新建并更换表格、参数或筛选值，可跨表对比。“撤销上次图表改动”恢复本次页面会话中的上一步已应用改动，不是多级历史。

主图支持自动、柱状、折线、独立分面及数值表，支持切换 X / Y 显示方向。高级设置位于主图上方，可调整统计方式、多条件筛选、名称和横轴顺序；“数据读取方式”默认自动，也可限制为列指标或行指标。行标识识别不正确时，可修正多级标识字段，或按原始数据行号独立展示。切换 X / Y 仅改变图表方向，不会转置源 Excel。

“本表分析建议”只依据当前数据表和已选参数生成趋势、排名或构成图，不会推荐其他表。推荐图用于辅助查看，主图参数仍在上方统一设置。

系列数量较多时保留全部选择并提示拥挤；分面图每页最多展示 6 张，可翻页查看。图表图片导出当前可见页；数值 CSV 包含当前筛选与聚合口径下的全部系列和数据行，不受图表分页或显示条数限制。页面数值表仅预览前 300 行。

## 统计口径与保存

- 自动统计是可修改的启发式默认值：普通数值通常求和，文本或编码通常非空计数，比例、价格等通常平均，累计字段通常取“最新值”。“最新值”指原表末行有效值，不自动按日期重排记录；库存等业务指标应自行核对口径。
- “总体比例”需在逐行模式选择分子和分母，按有效配对记录的分子合计除以分母合计；普通平均比例不等于总体比例。分母为零或缺少有效配对时留空。
- 缺失值不补零。不同时间粒度或年份口径自动独立分面；无年份月份不会推断跨年年份。同名字段、相同单位及实际 / 预测等业务口径仍需人工确认。
- 数值明细可选择相对第一组计算差值和变化率，前提是口径与单位相同；基准为零或缺失时变化率留空，不兼容的时间轴不计算组间差值。
- “保存分析”只保存已应用设置。当前对比与收藏保存在当前浏览器的本地存储，不是服务器共享配置，也不是数据快照；更换浏览器或清理站点数据可能丢失设置。收藏再次打开时使用最新已导入数据。
- 编辑预览或打开弹窗期间发现源数据更新，会提示“发现新的源数据”，当前输入先保留。点击“载入更新并核对”后再检查字段、筛选与系列；失效选择会提示修正，不自动替换成其他数据。

## 能力边界与文件位置

- 不直接支持 `.xls`；请先另存为 `.xlsx`。复杂多行表头、大量合并单元格、无字段名或仅以颜色表示业务含义的表格，不能保证自动识别正确，需手动修正区域和映射。
- 原表预览展示单元格内容及合并布局，不渲染内嵌图片、图表和完整 Excel 样式。公式使用文件上次保存的缓存结果，本工具不负责重新计算 Excel 公式。
- 跨表对比是各系列独立聚合后对齐，不会自动关联明细行、统一业务口径或推断销量下降原因。新版网页没有大模型自然语言分析入口。
- 导入数据：`output_file/warehouse.db`；数据源设置：`output_file/workspace.json`；手动识别规则：`output_file/recognition.json`。导入失败时保留该文件的上次数据；移走文件或切换目录不会自动删除已导入历史数据。
- 新版前端位于 `web/`，服务为 `server.py`，图表使用本地 ECharts 库并保留上游许可声明。

python -m unittest discover -s tests -v

    node $_.FullName

## 旧版兼容入口

保留原 Streamlit 页面供兼容使用：

```powershell
streamlit run app.py
```

旧入口与新版网页不是同一套界面，不包含上述全部图表映射与交互改进；日常使用建议启动 `server.py`。旧版的规则式问数不代表新版已实现大模型分析能力。
